# convex-example

A [Convex](https://convex.dev) backend whose HTTP endpoints are served by
[`@hectoday/http`](../../packages/http) through
[`@hectoday/convex`](../../packages/convex). This is the Hectoday version of the
[Hono with Convex](https://stack.convex.dev/hono-with-convex) guide.

## Layout

```
convex/
  schema.ts       # messages table
  messages.ts     # list / getByAuthor queries, send mutation
  http.ts         # Hectoday app + convexRouter (the default export)
  _generated/     # Convex codegen output (regenerated by `convex dev`)
```

`convex/http.ts` builds a normal Hectoday app and exports
`convexRouter(app)`. Every request is routed and validated by Hectoday, and the
Convex `ActionCtx` is exposed to handlers as `c.env`, so routes can call
`c.env.runQuery(...)` / `c.env.runMutation(...)`.

## Run it

This app needs a Convex deployment. From this directory:

```bash
npx convex dev
```

That provisions a dev deployment, regenerates `convex/_generated/`, and pushes
the functions. It prints your deployment's HTTP URL
(`https://<name>.convex.site`). Then:

```bash
# send a message
curl -X POST https://<name>.convex.site/postMessage \
  -H 'content-type: application/json' \
  -d '{"author":"ada","body":"hello"}'

# list messages by author
curl https://<name>.convex.site/listMessages/ada

# latest messages
curl https://<name>.convex.site/messages
```

> The committed `convex/_generated/` files are placeholders so the example
> type-checks before you connect a deployment. `npx convex dev` overwrites them
> with the real generated code.
